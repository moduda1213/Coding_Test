# KMP로 배열의 반복 패턴 찾기

## 1. 문제 상황

다음처럼 긴 숫자 배열이 주어진다. 배열을 만드는 짧은 패턴은 미리 알려져 있지 않다.

```text
[1, 2, 3, 1, 2, 3, 1, 2, 3, ...]       → [1, 2, 3]
[1, 4, 5, 4, 1, 2, 1, 4, 5, 4, 1, 2, ...] → [1, 4, 5, 4, 1, 2]
```

배열의 길이가 10,000이라면 패턴의 끝에서 배열이 끊길 수 있다. 예를 들어 길이 3인 패턴은 3,333번 반복된 뒤 첫 숫자 하나가 남는다. 여기서는 **패턴이 두 번 이상 완전히 등장하고, 끝에는 패턴의 일부가 붙어도 되는 경우**를 반복 패턴으로 인정한다.

배열의 값이 1~5 중 하나라는 사실은 비교 방법을 바꾸지 않는다. 패턴을 확정하려면 배열 전체를 확인해야 한다.

## 2. 핵심 아이디어: 앞과 뒤에서 같은 부분 찾기

먼저 짧은 배열을 보자.

```text
배열: [1, 2, 3, 1, 2, 3, 1]
        └──── 앞의 4개 ────┘
                 └──── 뒤의 4개 ────┘
```

앞의 4개와 뒤의 4개는 모두 `[1, 2, 3, 1]`이다. 전체 길이는 7이고, 앞뒤에서 겹치는 길이는 4다. 따라서 같은 숫자가 다시 나타나기 시작하는 간격은 `7 - 4 = 3`이다. 앞의 3개 `[1, 2, 3]`이 반복 패턴이다.

KMP의 **LPS 배열**은 각 위치까지 보았을 때, 앞부분과 뒷부분이 같은 최대 길이를 저장한다. LPS는 *Longest Proper Prefix which is also Suffix*의 약자다. 여기서 `proper`는 비교 대상 전체를 그대로 세지 않는다는 뜻이다.

```text
값:       1  2  3  1  2  3  1
인덱스:   0  1  2  3  4  5  6
lps:      0  0  0  1  2  3  4
```

예를 들어 `lps[4] = 2`는 `[1, 2, 3, 1, 2]`의 앞 2개와 뒤 2개가 `[1, 2]`로 같다는 뜻이다. 마지막 값 `lps[-1] = 4`는 **전체 배열의** 앞 4개와 뒤 4개가 같다는 뜻이다.

## 3. `j`가 의미하는 것

`i`는 지금 살펴보는 위치이고, `j`는 **현재 배열의 뒷부분과 일치하는 앞부분의 길이**다. 따라서 다음 값 `arr[i]`를 앞부분의 `arr[j]`와 비교한다.

```text
arr = [1, 2, 3, 1, 2, 3, 1]

i=3: arr[3]=1과 arr[0]=1이 같음 → j=1, lps[3]=1
i=4: arr[4]=2와 arr[1]=2가 같음 → j=2, lps[4]=2
i=5: arr[5]=3과 arr[2]=3이 같음 → j=3, lps[5]=3
i=6: arr[6]=1과 arr[3]=1이 같음 → j=4, lps[6]=4
```

값이 같으면 `j`를 1 늘린다. 어려운 부분은 값이 **다를 때**다.

## 4. 값이 다를 때: 왜 `j = lps[j - 1]`인가?

앞부분 `[1, 2, 1]`까지 일치해서 `j = 3`인 상황을 생각하자. 이제 다음 값이 기대한 값과 다르다.

```text
일치했던 부분: [1, 2, 1]

길이 2 후보:
앞의 2개         [1, 2]
일치 부분의 뒤 2개 [2, 1]  → 다르다

길이 1 후보:
앞의 1개         [1]
일치 부분의 뒤 1개 [1]     → 같다
```

`j -= 1`로 길이를 2로 바꾸면, 이미 불가능한 후보를 일치한다고 취급할 수 있다. `lps[j - 1]`에는 **방금 일치했던 부분에서 앞뒤가 같은 다음 길이**가 저장되어 있다. 이 예에서는 `lps[2] = 1`이므로 `j`가 3에서 1로 이동한다.

실제 오류가 나는 입력도 있다.

```text
배열: [1, 2, 1, 3, 1, 2, 1, 1]
마지막 값 직전: j = 3

올바른 이동: j = 3 → lps[2] = 1 → 0 → 마지막 1과 일치 → lps[7] = 1
잘못된 j -= 1: j = 3 → 2 → 마지막 1과 arr[2]가 같아서 lps[7] = 3으로 잘못 기록
```

### `j`의 이동과 `lps` 값은 다르다

```text
값:  [1, 1, 1, 1, 2]
lps: [0, 1, 2, 3, 0]
```

마지막 `2` **하나를 처리하는 동안** `j`는 `3 → 2 → 1 → 0`으로 이동한다. 그러나 마지막 위치에 **저장되는** `lps` 값은 최종 결과인 `0` 하나다. `while` 안에서 거쳐 간 `j` 값들을 각각의 `lps` 값으로 생각하면 혼동하기 쉽다.

## 5. 패턴 길이는 왜 `n - lps[-1]`인가?

전체 길이를 `n`, 마지막 LPS 값을 `L`이라고 하자. 앞의 `L`개와 뒤의 `L`개가 같다면 배열을 `n - L`칸 밀었을 때 두 부분이 겹쳐서 일치한다. 따라서 반복 간격, 즉 가장 짧은 패턴 후보의 길이는 다음과 같다.

```python
size = n - lps[-1]
pattern = arr[:size]
```

예를 들어 `[1, 2, 3, 1, 2, 3, 1]`은 `n = 7`, `lps[-1] = 4`이므로 `size = 3`이다. 이는 배열에서 `arr[i] == arr[i - 3]`이 `i >= 3`인 모든 위치에서 성립한다는 뜻이다.

길이가 10,000일 때 `[1, 2, 3]`이 반복되면 `size = 3`이고, `[1, 4, 5, 4, 1, 2]`가 반복되면 `size = 6`이다. 두 경우 모두 배열 끝에서 패턴이 일부만 나타난다.

## 6. 왜 `size * 2 <= n`을 검사하나?

`n - lps[-1]`은 **반복 간격 후보**만 알려 준다. 그 묶음이 두 번 완전히 등장했다는 보장은 없다.

```text
배열: [2, 5, 2]
lps:  [0, 0, 1]
size = 3 - 1 = 2

[2, 5] [2]
 완전   일부
```

이 배열은 2칸 간격으로 일부가 반복되지만 `[2, 5]`가 두 번 완전히 나오지는 않았다. 그래서 두 번 이상의 **완전한 반복**을 요구할 때 `size * 2 <= n`을 검사한다.

```text
[2, 5, 2]       → 2 * 2 > 3: 인정하지 않음
[2, 5, 2, 5, 2] → 2 * 2 <= 5: 인정함. 마지막 2는 일부 반복
```

끝에 일부가 남는 것도 허용하지 않고 패턴이 **정확히 정수 번** 반복되어야 한다면 `n % size == 0`도 검사한다. 길이 10,000인 배열에 길이 3 또는 6인 패턴을 허용하려면 이 나머지 검사는 하지 않는다.

## 7. 파이썬 코드

```python
def find_pattern(arr):
    n = len(arr)
    if n == 0:
        return None

    lps = [0] * n
    j = 0

    for i in range(1, n):
        # 지금 값이 다르면, 앞뒤가 같을 수 있는 더 짧은 길이로 이동한다.
        while j > 0 and arr[i] != arr[j]:
            j = lps[j - 1]

        if arr[i] == arr[j]:
            j += 1
            lps[i] = j

    size = n - lps[-1]

    # 완전한 패턴이 최소 두 번 등장해야 한다.
    if size * 2 > n:
        return None

    return tuple(arr[:size])


arrays = [
    ([1, 2, 3] * 3334)[:10000],
    ([1, 4, 5, 4, 1, 2] * 1667)[:10000],
]

# patterns[i]에 arrays[i]의 패턴을 저장한다.
patterns = [find_pattern(arr) for arr in arrays]
print(patterns)
# [(1, 2, 3), (1, 4, 5, 4, 1, 2)]
```

같은 패턴을 가진 배열들을 묶으려면 패턴을 딕셔너리의 키로 사용한다.

```python
from collections import defaultdict

groups = defaultdict(list)
for index, arr in enumerate(arrays):
    pattern = find_pattern(arr)
    if pattern is not None:
        groups[pattern].append(index)
```

## 8. 시간·공간 복잡도와 한계

- 배열 길이가 `N`일 때 LPS 계산은 **시간 `O(N)`**, **공간 `O(N)`**이다. 불일치 때 `j`가 여러 번 줄어들 수 있지만, 전체 과정에서 증가한 만큼만 줄어들 수 있어 총 이동 횟수는 `N`에 비례한다.
- 배열이 여러 개라면 전체 시간은 **모든 배열 길이의 합에 비례**한다.
- 마지막 숫자 하나가 패턴을 깨뜨릴 수도 있으므로, **배열 전체가** 패턴을 따르는지 확정하려면 최악의 경우 끝까지 확인해야 한다.
- 이 방법은 **배열 전체의 반복 패턴**을 찾는다. 배열 중간에 잠깐 등장하는 반복 부분만 찾는 문제에는 다른 기준과 알고리즘이 필요하다.

## 기억할 세 가지

1. `lps[i]`: `i`까지의 배열에서 앞부분과 뒷부분이 같은 최대 길이.
2. `j = lps[j - 1]`: 불일치하면 실제로 일치할 수 있는 다음 길이로 이동.
3. `n - lps[-1]`: 전체 배열의 가장 짧은 반복 간격. 두 번 완전히 반복되었는지는 `size * 2 <= n`으로 확인.
