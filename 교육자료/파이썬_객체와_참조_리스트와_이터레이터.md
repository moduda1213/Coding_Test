# 자바 개발자를 위한 파이썬 객체와 참조: 리스트와 이터레이터를 그림으로 이해하기

파이썬에서 리스트를 일정한 개수씩 묶는 코드를 보다가 다음 표현을 만났다.

```python
scores = [1, 2, 3, 4, 5, 6]
score_iter = iter(scores)
m = 3

for group in zip(*[score_iter] * m):
    print(group)
```

```text
(1, 2, 3)
(4, 5, 6)
```

왜 리스트를 직접 넣지 않고 이터레이터를 만들까? `[score_iter] * m`은 이터레이터를 복사할까? 앞의 `*`는 무엇을 할까?

자바를 공부했다면 참조라는 개념은 익숙할 것이다. 하지만 파이썬에서는 정수까지 객체이고, 대입과 리스트 반복이 동작하는 방식도 정확히 구분해야 한다. 이 글에서는 객체와 참조에서 출발해 위 코드의 실행 과정까지 연결해 본다.

> 이 글의 화살표는 객체에 대한 참조를 뜻한다. 메모리 그림은 이해를 위한 개념도이며, 실제 메모리 배치를 그대로 표현하지 않는다. 구현에 관한 설명은 CPython 기준임을 따로 표시한다.

## 1. 객체와 참조: 변수는 객체에 붙인 이름이다

파이썬에서는 정수, 문자열, 리스트, 함수 등이 모두 객체다. 변수는 객체를 가리키는 이름이라고 이해하면 된다.

```python
a = [1, 2, 3]
b = a
```

이 코드는 리스트를 두 개 만들지 않는다. 하나의 리스트에 `a`와 `b`라는 이름이 연결된다.

```text
a ──┐
    ├──→ 리스트 객체 [1, 2, 3]
b ──┘
```

자바에서 두 참조형 변수가 같은 `ArrayList`를 가리키는 상황과 비슷하다.

```java
List<Integer> a = new ArrayList<>();
List<Integer> b = a;
```

다만 파이썬에서는 자바의 기본형 `int`와 달리 정수도 객체다. 따라서 “정수는 값이 복사되고, 리스트는 참조가 복사된다”라고 구분하면 정확하지 않다. 파이썬의 대입은 이름을 객체에 연결한다.

### 값이 같은지와 같은 객체인지는 별개다

```python
a = [1, 2]
b = [1, 2]
c = a

print(a == b)  # True
print(a is b)  # False
print(a is c)  # True
```

| 표현 | 확인하는 것 |
| --- | --- |
| `a == b` | 두 객체가 같은 값으로 비교되는가? |
| `a is b` | 두 이름이 동일한 객체를 가리키는가? |

`==`의 구체적인 비교 방식은 타입이 정의한다. 리스트는 요소의 값을 비교한다. 숫자나 문자열의 값을 비교할 때는 `is`가 아닌 `==`를 사용한다.

## 2. 재대입과 객체 수정은 다르다

### 객체 수정: 화살표가 가리키는 대상의 내용 변경

```python
a = [1, 2, 3]
b = a
b.append(4)

print(a)  # [1, 2, 3, 4]
print(b)  # [1, 2, 3, 4]
```

```text
a ──┐
    ├──→ [1, 2, 3, 4]
b ──┘
```

같은 리스트를 수정했으므로 두 이름을 통해 같은 변경 결과가 보인다.

### 재대입: 이름의 화살표를 다른 객체에 연결

```python
a = [1, 2, 3]
b = a
b = [9, 8]

print(a)  # [1, 2, 3]
print(b)  # [9, 8]
```

```text
a ──→ [1, 2, 3]
b ──→ [9, 8]
```

`b = [9, 8]`은 기존 리스트를 수정하지 않는다. 새 리스트를 만들고 `b`를 연결한다.

### 정수는 내용을 변경할 수 없는 객체다

```python
a = 10
b = a
a = a + 1

print(a)  # 11
print(b)  # 10
```

기존 `10` 객체를 `11`로 수정한 것이 아니다. 덧셈 결과인 `11` 객체에 이름 `a`를 연결한 것이다.

| 구분 | 대표적인 타입 |
| --- | --- |
| 변경 가능 | `list`, `dict`, `set` |
| 변경 불가능 | `int`, `float`, `str`, `tuple` |

튜플은 자신이 담은 참조의 구성을 바꿀 수 없다는 뜻이다. 튜플이 참조하는 리스트까지 변경 불가능해지는 것은 아니다.

```python
data = ([1, 2],)
data[0].append(3)
print(data)  # ([1, 2, 3],)
```

## 3. 컨테이너와 리스트에는 무엇이 들어갈까?

컨테이너는 다른 객체를 요소로 담는 객체를 뜻한다. 리스트, 튜플, 딕셔너리, 집합이 대표적이다.

리스트를 이해할 때는 각 칸에 객체 자체가 통째로 들어간다고 생각하기보다, 객체에 대한 참조가 들어간다고 생각하면 좋다.

```python
a = [1, 2]
box = [a]
```

```text
a ─────────────────→ [1, 2]
                        ↑
                        │
box ──→ 리스트 [ ● ] ───┘
```

`box`는 변수 이름 `a`를 담지 않는다. `a`가 가리키던 리스트에 대한 참조를 담는다.

```python
a.append(3)
print(box)  # [[1, 2, 3]]

a = [9]
print(box)  # [[1, 2, 3]]
```

재대입 이후에는 다음처럼 된다.

```text
a ─────────────────→ [9]

                     [1, 2, 3]
                         ↑
                         │
box ──→ 리스트 [ ● ] ────┘
```

`a`의 연결이 바뀌어도 `box`의 첫 번째 칸에 있던 참조는 그대로다.

## 4. 리스트 반복과 객체 복사는 다르다

```python
it = iter([1, 2, 3])
refs = [it] * 3
```

`refs`의 구조는 `[it, it, it]`이다. `[[it], [it], [it]]`가 아니다.

```text
refs ──→ 리스트 객체 하나
         ┌─────┬─────┬─────┐
         │  ●  │  ●  │  ●  │
         └──┬──┴──┬──┴──┬──┘
            │     │     │
            └─────┼─────┘
                  ▼
          이터레이터 객체 하나
```

정확한 설명은 다음과 같다.

> `[it] * 3`은 같은 이터레이터 객체에 대한 참조 세 개를 담은 리스트를 만든다. 이터레이터 자체를 복제하지 않는다.

동일한 객체인지 확인할 수도 있다.

```python
print(refs[0] is refs[1] is refs[2])  # True

print(next(refs[0]))  # 1
print(next(refs[1]))  # 2
print(next(refs[2]))  # 3
```

어느 칸을 통해 접근해도 같은 이터레이터를 사용하므로 진행 위치가 공유된다.

### 같은 원리로 발생하는 중첩 리스트 주의점

```python
rows = [[]] * 3
rows[0].append(1)

print(rows)  # [[1], [1], [1]]
```

내부 리스트 하나를 세 칸이 함께 참조하기 때문이다. 서로 다른 내부 리스트가 필요하면 각각 생성해야 한다.

```python
rows = [[] for _ in range(3)]
rows[0].append(1)

print(rows)  # [[1], [], []]
```

`a.copy()`나 `a[:]`도 바깥 리스트만 새로 만드는 얕은 복사다. 내부 객체까지 자동으로 복제하지는 않는다.

## 5. iterable, iterator, iter(), next() 구분하기

| 용어 | 의미 | 예시 |
| --- | --- | --- |
| iterable | 이터레이터를 얻어 반복할 수 있는 객체 | 리스트, 튜플, `range` |
| iterator | 다음 값을 제공하며 순회 상태를 가진 객체 | 리스트 이터레이터, 제너레이터 |
| `iter()` | 객체로부터 이터레이터를 얻는 함수 | `iter(scores)` |
| `next()` | 이터레이터에서 다음 값을 요청하는 함수 | `next(score_iter)` |

이터레이터도 iterable이다. 특히 이터레이터에 `iter()`를 적용하면 자기 자신을 반환한다.

```python
items = [10, 20, 30]
it = iter(items)

print(iter(it) is it)  # True
```

### 리스트를 변환하거나 복사하는 것이 아니다

```python
items = [10, 20, 30]
it = iter(items)

print(type(items))  # <class 'list'>
print(type(it))     # <class 'list_iterator'>
```

리스트는 그대로 있고, 리스트를 순회하는 별도의 객체가 만들어진다.

```text
items ──→ 리스트 [10, 20, 30]
                  ↑
                  │ 참조
it ──→ 리스트 이터레이터
       ├─ 원본 리스트 참조
       └─ 다음 읽기 위치: 0
```

### next()를 호출할 때 진행한다

```python
print(next(it))  # 10
print(next(it))  # 20
print(next(it))  # 30
# next(it)      # StopIteration 발생

print(items)    # [10, 20, 30]
```

이터레이터가 값을 소비한다는 말은 원본 리스트의 요소를 삭제한다는 뜻이 아니다. 이터레이터의 순회 위치가 진행한다는 뜻이다.

리스트 이터레이터는 개념적으로 다음 동작을 한다.

```text
다음 위치의 요소가 있으면:
    해당 요소를 반환하고 위치를 한 칸 진행
없으면:
    StopIteration 발생
```

이 설명은 리스트 이터레이터에 대한 것이다. 모든 이터레이터가 인덱스와 길이를 이용하는 것은 아니다. 파일을 읽거나 값을 계산해서 제공하는 이터레이터도 있다.

### for문도 내부에서 이터레이터를 사용한다

```python
for value in items:
    print(value)
```

위 코드는 개념적으로 다음 과정이다.

```python
it = iter(items)

while True:
    try:
        value = next(it)
    except StopIteration:
        break

    print(value)
```

일반적인 반복에서는 `for`가 처리하므로 직접 `iter()`를 호출할 필요가 없다. 진행 위치를 직접 다루거나 여러 곳에서 공유하려고 할 때 명시적으로 사용한다.

소진된 리스트 이터레이터를 처음부터 읽으려면 원본 리스트로 새 이터레이터를 만든다.

```python
it = iter(items)
```

`iter(it)`는 같은 이터레이터를 반환하므로 초기화 방법이 아니다.

## 6. 리스트와 이터레이터의 메모리와 사용처

CPython의 리스트는 요소 객체에 대한 참조들을 배열 형태로 보관한다. 요소 객체 자체가 그 배열 안에 연속해서 저장된다는 뜻은 아니다. 리스트는 크기가 늘어날 때를 대비해 여유 공간도 확보할 수 있다.

리스트 이터레이터는 원본 리스트에 대한 참조와 순회 위치 등 소량의 상태를 관리한다.

| 대상 | 공간에 대한 설명 |
| --- | --- |
| 요소 n개를 담은 리스트 | 참조 저장 공간 O(n), 요소 객체 공간은 별도 |
| 그 리스트의 이터레이터 | 추가 공간 O(1) |

```python
items = list(range(1_000_000))
it = iter(items)
```

여기서 이터레이터를 만들었다고 백만 개짜리 리스트가 사라지지 않는다. 이터레이터는 원본 리스트의 요소를 복사하지 않지만, 원본 리스트는 여전히 필요하다.

CPython에서는 리스트와 리스트 이터레이터 모두 프로세스의 힙 메모리에 존재하는 객체다. 하나는 스택, 다른 하나는 힙에 저장된다는 식으로 구분하지 않는다. 중요한 차이는 저장 장소보다 각 객체가 보관하는 정보다.

### 언제 무엇을 사용할까?

- 인덱스로 접근하고, 정렬하거나 여러 번 순회하려면 리스트가 편하다.
- 다음 값을 하나씩 요청하고, 순회 상태를 유지하려면 이터레이터가 적합하다.
- 모든 결과를 미리 만들 필요가 없다면 제너레이터로 메모리를 줄일 수 있다.

```python
# 리스트: 제곱 결과를 모두 만들어 저장
squares_list = [x * x for x in range(1_000_000)]

# 제너레이터: 요청할 때마다 다음 제곱값 계산
squares_iter = (x * x for x in range(1_000_000))

print(next(squares_iter))  # 0
print(next(squares_iter))  # 1
```

제너레이터는 이터레이터의 한 종류다. 모든 이터레이터가 메모리를 적게 사용하는 것은 아니며, 유지하는 원본 데이터와 내부 상태에 따라 달라진다.

## 7. zip과 별표의 역할

`zip`은 전달받은 각 iterable에서 값을 하나씩 꺼내 튜플로 묶는 이터레이터를 반환한다.

```python
for pair in zip([1, 2], [10, 20]):
    print(pair)
```

```text
(1, 10)
(2, 20)
```

인자가 하나라면 길이 1인 튜플을 만든다.

```python
print(list(zip([1, 2, 3])))
# [(1,), (2,), (3,)]
```

`(1,)`의 쉼표는 요소 하나를 가진 튜플임을 나타낸다.

### 함수 호출에서 *는 요소를 개별 인자로 펼친다

```python
values = [1, 2, 3]

print(values)   # [1, 2, 3]
print(*values)  # 1 2 3
```

`print(*values)`는 `print(1, 2, 3)`처럼 호출한다는 뜻이다.

다음 표현에서는 두 별표의 역할이 다르다.

```python
zip(*([score_iter] * m))
#   ↑              ↑
# 인자 펼치기     리스트 반복
```

괄호를 추가해 계산할 부분을 드러내면 이해하기 쉽다. `zip(*[score_iter] * m)`과 같은 의미다.

### 헷갈리는 표현 비교

아래 표에서 `it`는 리스트 이터레이터이고 `m`은 양의 정수다.

| 표현 | 의미 또는 결과 |
| --- | --- |
| `it * m` | 리스트 이터레이터는 곱셈을 지원하지 않아 오류 |
| `[it] * m` | 같은 이터레이터의 참조 m개를 담은 리스트 |
| `zip([it] * m)` | 리스트 하나를 인자로 전달 |
| `zip(*([it] * m))` | 같은 이터레이터를 m개의 인자로 전달 |

`iter`는 내장 함수 이름이므로 이터레이터 변수에는 `it`나 `score_iter` 같은 이름을 사용하는 것이 좋다.

## 8. zip(*[score_iter] * m)의 실행 과정

```python
scores = [1, 2, 3, 4, 5, 6, 7]
score_iter = iter(scores)
m = 3

groups = zip(*([score_iter] * m))
```

### 1단계: 같은 참조를 반복한 리스트 생성

```python
[score_iter] * 3
# [score_iter, score_iter, score_iter]
```

이터레이터 하나를 세 칸이 함께 가리킨다.

### 2단계: 개별 인자로 펼치기

```python
zip(*([score_iter] * 3))

# 다음 호출과 같은 의미
zip(score_iter, score_iter, score_iter)
```

이터레이터에 `iter()`를 적용하면 자기 자신을 반환하므로, `zip`의 세 인자는 같은 순회 상태를 공유한다.

### 3단계: 반복할 때 각 인자에서 값을 요청

`zip`을 생성한 것만으로 원본 요소를 꺼내지는 않는다. `for`, `next()`, `list()` 등으로 결과를 요청할 때 값을 읽는다.

| 결과 요청 | 첫 번째 인자 | 두 번째 인자 | 세 번째 인자 | 반환 |
| --- | --- | --- | --- | --- |
| 첫 번째 | 1 소비 | 2 소비 | 3 소비 | `(1, 2, 3)` |
| 두 번째 | 4 소비 | 5 소비 | 6 소비 | `(4, 5, 6)` |
| 세 번째 | 7 소비 | 소진되어 종료 | 요청하지 않음 | 없음 |

```python
print(list(groups))
# [(1, 2, 3), (4, 5, 6)]
```

`7`은 읽었지만 묶음을 완성하지 못했으므로 결과에 포함되지 않는다. 기본 `zip`은 어느 한 이터레이터가 소진되면 종료한다.

### 리스트를 그대로 세 번 전달하면?

```python
scores = [1, 2, 3]

print(list(zip(scores, scores, scores)))
# [(1, 1, 1), (2, 2, 2), (3, 3, 3)]
```

리스트에는 `iter()`를 호출할 때마다 별도의 이터레이터가 만들어진다. `zip`의 각 인자가 독립적으로 처음부터 진행하므로 같은 위치의 값끼리 묶인다.

```text
zip(scores, scores, scores)
    ├─ 이터레이터 A: 1 → 2 → 3
    ├─ 이터레이터 B: 1 → 2 → 3
    └─ 이터레이터 C: 1 → 2 → 3

zip(score_iter, score_iter, score_iter)
    └─ 이터레이터 하나: 1 → 2 → 3 → ...
```

### zip([score_iter] * 3)은?

```python
score_iter = iter([1, 2, 3])
result = list(zip([score_iter] * 3))
```

개념적인 결과는 다음과 같다. 실제 출력에는 객체의 표현이 표시된다.

```text
[(score_iter,), (score_iter,), (score_iter,)]
```

바깥 리스트에서 이터레이터 객체를 하나씩 꺼내 튜플로 묶을 뿐, 그 이터레이터 내부의 숫자는 꺼내지 않는다.

```python
print(next(score_iter))  # 여전히 1
```

### 시간과 추가 공간

요소 수를 n, 묶음 크기를 m이라고 하자. 둘 다 양의 정수인 경우를 기준으로 한다.

- `[score_iter] * m`과 `zip`의 준비에는 O(m) 시간과 추가 공간이 필요하다.
- 전체를 끝까지 순회하는 시간은 준비 비용을 포함해 O(n + m)이다.
- 결과를 하나씩 처리하면 묶음을 유지하는 데 O(m) 추가 공간이 필요하다.
- `list(groups)`로 모든 결과를 저장하면 결과 요소를 보관하는 데 O(n) 공간이 추가로 필요하다.

원본 리스트가 차지하는 공간은 위의 추가 공간과 별도다.

## 9. 남는 요소 처리와 읽기 쉬운 대안

먼저 묶음 크기 `m`은 양의 정수로 제한하는 것이 좋다.

```python
if m <= 0:
    raise ValueError("묶음 크기는 양의 정수여야 합니다.")
```

### 남는 요소를 버리려면

```python
it = iter([1, 2, 3, 4, 5, 6, 7])

for group in zip(*([it] * 3)):
    print(group)
```

```text
(1, 2, 3)
(4, 5, 6)
```

### 리스트에서 남는 요소도 포함하려면

슬라이싱으로 의도를 직접 드러낼 수 있다.

```python
items = [1, 2, 3, 4, 5, 6, 7]
m = 3

for i in range(0, len(items), m):
    print(items[i:i + m])
```

```text
[1, 2, 3]
[4, 5, 6]
[7]
```

각 슬라이스는 새로운 리스트다. 마지막 슬라이스는 요소가 m개보다 적을 수 있다.

### Python 3.12 이상에서는 itertools.batched

```python
from itertools import batched

items = [1, 2, 3, 4, 5, 6, 7]

for group in batched(items, 3):
    print(group)
```

```text
(1, 2, 3)
(4, 5, 6)
(7,)
```

`batched`는 iterable을 일정한 크기의 튜플로 묶으며 마지막의 짧은 묶음도 반환한다. Python 3.12부터 사용할 수 있다.

Python 3.13 이상에서는 `batched(items, 3, strict=True)`로 마지막 묶음의 크기가 부족할 때 `ValueError`를 발생시킬 수도 있다.

### 빈 칸을 채워서 크기를 맞추려면

```python
from itertools import zip_longest

it = iter([1, 2, 3, 4, 5, 6, 7])

for group in zip_longest(*([it] * 3), fillvalue=None):
    print(group)
```

```text
(1, 2, 3)
(4, 5, 6)
(7, None, None)
```

묶음 크기가 변수라면 `a, b, c` 같은 고정된 변수 개수 대신 `group`으로 받으면 된다.

## 10. 복습 문제와 면접 답변

### 문제 1. 출력 결과는?

```python
a = [1, 2]
b = a
a = [3, 4]

print(b)
```

**정답: `[1, 2]`**

`a`를 재대입해도 `b`는 원래 리스트를 계속 참조한다.

### 문제 2. 리스트 객체는 몇 개일까?

```python
rows = [[]] * 3
```

**최종 구조에는 바깥 리스트 하나와 내부 빈 리스트 하나가 있다.** 바깥의 세 칸이 같은 내부 리스트를 참조한다. 표현식 평가 도중 사용되는 임시 객체는 여기서 세지 않는다.

### 문제 3. 다음 값은 무엇일까?

```python
it = iter([10, 20, 30, 40])
refs = [it] * 2

print(next(refs[0]))
print(next(refs[1]))
```

**정답: `10`, `20`**

같은 이터레이터의 순회 상태를 공유한다.

### 면접에서 짧게 설명한다면

> “`[score_iter] * m`은 같은 이터레이터 객체에 대한 참조 m개를 담은 리스트를 만듭니다. 앞의 `*`는 그 요소들을 함수의 개별 인자로 펼칩니다. `zip`의 각 인자가 같은 이터레이터를 공유하므로, 값을 요청할 때마다 순서대로 소비해서 m개씩 묶습니다. 기본 `zip`에서는 마지막 묶음이 m개를 채우지 못하면 반환하지 않습니다.”

그림으로 설명한다면 다음 세 줄을 순서대로 그리면 된다.

```text
1. [ 참조, 참조, 참조 ] ──→ 같은 이터레이터 하나

2. zip(*([it] * 3)) → zip(it, it, it)

3. next(it), next(it), next(it) → (1, 2, 3)
```

파이썬 코드를 읽을 때는 어떤 객체가 생성되는지, 어떤 이름과 컨테이너가 그 객체를 참조하는지, 객체를 수정하는지 아니면 연결만 바꾸는지를 나누어 살펴보자. 이 구분이 익숙해지면 리스트 복사와 이터레이터 공유도 같은 원리로 설명할 수 있다.
